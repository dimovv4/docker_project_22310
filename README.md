# Проект: Контейнеризация на уеб приложение с Docker Compose

Този проект представлява напълно функционално уеб приложение, състоящо се от два отделни компонента (Бекенд услуга и База данни), което е контейнеризирано и се управлява централизирано чрез Docker Compose според изискванията на заданието.

---

## 1. Структура на проекта

Проектът е организиран в следната файлова структура:

```text
docker-project/
├── app.js               # Главен сорс код на бекенд приложението (Node.js + Express)
├── package.json         # Дефиниция на проекта и неговите зависимости
├── Dockerfile           # Инструкции за изграждане на Docker образа на бекенда
├── .dockerignore        # Списък с файлове, които Docker да игнорира при компилация
├── compose.yml          # Конфигурационен файл за Docker Compose (оркестрация)
└── README.md            # Документация на проекта (настоящият файл)
```

---

## 2. Как работи всеки от компонентите

Проектът използва двукомпонентна (Two-tier) архитектура:

    1. Бекенд услуга (backend):

        Изградена е с помощта на платформата Node.js и уеб рамката Express.

        Слуша за входящи HTTP заявки на порт **5000**.

        Основната ѝ функция е да приеме заявка на главния адрес (/), да направи тестов въпрос към базата данни и да върне JSON отговор към клиента, потвърждаващ статуса на системата.

    2. База данни (db):

        Използва официалния сертифициран лек образ PostgreSQL 15 (Alpine).

        Слуша на стандартния порт **5432**.

        За да се осигури персистентност (устойчивост) на данните и те да не се изгубят при спиране или рестартиране на контейнера, е конфигуриран споделен Docker Volume, наречен **postgres_data**.

---

## 3. Комуникация между услугите
Комуникацията е реализирана по сигурен и изолиран начин, следвайки добрите практики за контейнеризация:

    При стартиране Docker Compose автоматично създава изолирана виртуална мрежа за този проект.

    Вместо да използва локален адрес (localhost), бекенд контейнерът се свързва към базата данни чрез хост името db (което съвпада точно с името на услугата за база данни в compose.yml).

    Вграденият DNS сървър на Docker автоматично разпознава хост името db и пренасочва вътрешния трафик към правилния IP адрес на контейнера с PostgreSQL.

    Използвана е директивата depends_on, която гарантира, че бекендът ще изчака стартирането на базата данни, преди самият той да се пусне.

---

## 4. Как се изграждат и стартират контейнерите

Предварителни изисквания

Уверете се, че на компютъра ви е инсталиран и стартиран Docker Desktop.
Стъпки за локално стартиране:

    1. Отворете терминала (CMD, PowerShell или Terminal) в папка docker-project.

    2. Изпълнете следната команда, за да изградите локалния образ за бекенда и да стартирате цялата инфраструктура наведнъж в фонов режим:
    ```text
    docker compose up --build -d
    ```
    3. Изчакайте няколко секунди услугите да се инициализират.

    4.  Отворете уеб браузър и посетете адрес:
    http://localhost:5000

    При успешно стартиране ще получите следния JSON отговор:
    ```text
    {
    "status": "success",
    "message": "Бекендът и Базата данни работят отлично в Docker!"
    }
    ```

    Спиране на проекта:

    За да спрете контейнерите и да освободите портовете на компютъра си, изпълнете:
    ```
    docker compose down
    ```
